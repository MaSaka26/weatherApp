# weatherAPP

一个深色玻璃拟态的天气应用。数据来自 Open-Meteo（免费、无需 Key），界面为自定义的高 DPI 仪表盘风格，桌面与移动端分别布局。

当前仓库只维护一代实现：

| 目录 | 说明 |
| --- | --- |
| `weatherApp-VUE3/` | **唯一主工程**。Vite 8 + Vue 3.5 + Pinia + vue-router + Highcharts 13。 |

> 最早的原生单文件版 `weather.html`（167 KB，无构建、双击即开）已在 `a7ebabe` 删除，需要时可从 Git 历史 `e1105ff` 取回；不再维护。

## 快速开始

```bash
cd weatherApp-VUE3
npm install
npm run dev        # http://localhost:5173
```

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动开发服务器（HMR） |
| `npm run build` | 生产构建到 `dist/` |
| `npm run preview` | 预览生产构建 |
| `npm run lint` | oxlint + eslint，**必须 0 错** |
| `npm run format` | Prettier 格式化 `src/` |

> 环境要求：Node `^22.18.0 || >=24.12.0`。

## 功能

**打开就是完整页面，没有整页 loading**
- 输入网址进来直接画出整个仪表盘（六卡 / 逐小时 / 16 天 / 生活指数都在），不再先给一个转圈页等数据
- 首次访问、本地还没有缓存时，所有数字用 **0 占位**（温度 `0°`、湿度 `0%`、气压 `0`、紫外线与日出日落显示 `—`），骨架结构完整
- 之后每次打开优先读 `localStorage` 里上一次成功拿到的**主天气 + 位置**（`weather:last-good:v1`，24 小时内有效），所以第二次起连数字都是真的，只是可能比此刻晚几分钟
- 数据到达后原地注入更新，页面不闪、不重排、不回到顶部
- 数字和表盘不是「跳」过去的：温度、湿度 / 气压 / 紫外线三颗环、体感指针、日出日落进度都走 **1 秒缓出补间**，从 0 扫到真实值。**缓存命中时也从 0 扫一遍**——首个值虽然已经是真的，但直接落位会让画面「啪」地出现，少了数据被取回来的过程感；统一从 0 长起来，每次打开都有同一段生长动画
- 风向指针初始停在正北 0°，数据到达后 **顺时针**转到「风向 + 180」的目标刻度（+180 是让它指向风吹去的方向）。首次转向刻意不走最短路径——走最短路径会出现逆时针倒甩，与「先朝北再顺时针转」矛盾；之后的每 6 分钟刷新仍走最短边，避免 350° → 10° 时倒甩 340°
- 右上角刷新按钮在请求期间旋转图标（`aria-busy`），**点它手动刷新也不会切整页 loading**，屏幕上始终有内容可看
- 过期自动补拉：每分钟检查一次，距上次成功满 **6 分钟**才真正发请求（节流，不是每 6 分钟硬拉一把）；页面在后台时不请求，切回前台立刻补上
- 失败降级：数据更新失败不抹掉页面，只在底部那行小字变暖色提示「数据更新失败 · 原因」；只有连定位坐标都拿不到、屏幕上真的一无所有时才整页报错
- 地名与数据永远**同一拍落地**：切城市时不会出现「新城市名 + 旧城市数字」或「新数字 + 旧城市名」的错配；若首屏天气请求失败，解析出的新地名会挂起，等下一次请求成功才一起生效

**顶部**
- 实时温度、天气状况、今日最高/最低
- 右侧时钟：精确到秒的本地时间 + 日期 + 当年第几天
- 城市搜索：本地 3000+ 地名候选词（省/市/区县三级），输入即出下拉，选中后定位

**九卡详情**（体感、风速、湿度、气压、紫外线、日出日落，可再展开三张）
- 体感：指针表盘；风速：罗盘；湿度/气压：环形表盘；紫外线：UV 表盘；日出日落：弧形轨迹（九卡桌面版改用横线轨道 + 光点）
- 默认 **6 张**：手机 3 列 × 2 行、平板 3 列 × 2 行、桌面一行六列
- 首页「天气详情」标题右侧有 **6 张 / 9 张** 切换钮（和 16 天预报的「列表 / 曲线」同一套样式），点一下就地展开或收起，不必进设置面板
- 切换走两段式补间（200ms + 360ms）：展开是往下长出来；收起时先花 200ms 让三张新卡在**原地**淡出（这一步列数和卡片宽度都不动），再花 360ms 切列、把高度收回去，收完才真正卸载。之所以拆成两段：九卡五列每张 238px、六卡六列每张 197px，`grid-template-columns` 的轨道数变了浏览器没法插值，宽度是瞬跳的；挤在一帧里会变成「卡片先猛地变窄、再慢慢变矮」，拆开以后跳变落在三张卡刚消失、注意力还在它们身上的那一刻。日落卡另有一段上滑位移（FLIP），否则它在重排那一帧会往上跳一大截；系统开启「减少动态效果」时直接跳变
- 设置面板「卡片数量」与首页那颗切换钮是**同一个值**，改哪边都会一起变
- 「左右 / 上下」图文布局可在设置面板切换

**第 7–9 张：空气质量 / 能见度 / 降水量**（9 张模式才出现）
- 空气质量：主值 AQI（美国 EPA 0–500 刻度，文字等级沿用「优 / 良 / 轻度污染 / 中度污染 / 重度污染 / 严重污染」）+ PM2.5 / PM10 两行小字 + 环形表盘，环心是通风图标
- 能见度：主值公里（接口给米，展示按 km），分档「浓雾 < 1 / 有雾 < 5 / 轻雾 < 10 / 通透 < 20 / 极佳 ≥ 20」，环心是眼睛图标
- 降水量：主值毫米（当前小时的降水量），分档按中国气象局小时雨量标准「无降水 < 0.05 / 小雨 < 2.5 / 中雨 < 8 / 大雨 < 16 / 暴雨 ≥ 16」，环心是云和雨滴图标
- 桌面 9 张排成 **5 + 4**：第一行 5 张各一格，第二行降水量 / 空气质量 / 能见度各一格 + 日出日落占两格，两行右边缘对齐。日出日落通两格是因为九卡桌面版把它换成横线轨道（左右两端日出/日落时间、中间进度条 + 光点），单格宽里光点会和两端时间打架，横线挤不下
- 手机 9 张 = 3 + 3 + 3，正好三行填满，末张不跨格
- 空气质量走独立接口且懒加载：先渲染天气，AQI 到了再补进卡片，**不占用首屏等待时间**
- 能见度和降水量不需要额外请求，直接从已有的 `current.visibility` / `current.precipitation` 读

**天气预警**（夹在详情卡与逐小时之间）
- 数据来自中央气象台 `/rest/findAlarm`，免 Key、带 `Access-Control-Allow-Origin: *`，浏览器可直连
- **只有本地有预警时才出现**，没有就整块不渲染 —— 空态是常态，留一张「无预警」的空卡只会占地方
- 不显示标题栏和「多少条」，只留预警卡片本体；每条整块毛玻璃按级别染色（蓝/黄/橙/红：背景、边框、级别文字同一套色），不再是左侧一条色条 + 官方预警图标（125×94 PNG，接口直接给 URL）+ 类型 + 级别 + 区域与发布时间；按级别从高到低排，最多 3 条
- 点整条在新窗口打开 NMC 详情页（详情页没有 CORS 头，正文取不到，只能跳转）
- 「本地」判定：接口只能按**省**筛（市县无参数），所以取回一省列表后，用标题里的区域串匹配当前城市名（`湖北省荆州市松滋市气象台发布…` 命中「松滋」即算本地）
- **接口失败与「确实无预警」分开处理**：超时 / 非 200 / 网络被拦时显示一行中性灰玻璃提示「预警信息暂时获取失败」+「刷新」按钮，只重试预警这一路、不重拉整个天气；点后按钮变「重试中…」并旋转，成功即恢复卡片。成功但 0 条仍是整块隐藏（不误报成错误），境外城市无省名也算正常空态。提示条刻意不用红/黄等预警色，避免和灾害级别配色语义打架

**逐小时预报**
- 横向滚动 24 小时，含温度、天气图标、降水概率
- 昼夜按接口返回的 `is_day` 逐小时判定，不再用固定时间段猜测

**降水预报条目**
- 左侧：标题「降水预报」+ 一句结论（如「正在下雨」「约 2 小时后转停」「未来 24 小时无雨」）
- 结论下方一条 **12 小时强度柱条**：一小时一格，柱高按 0–3 档递进，颜色取自雷达色带的中层，和右侧回波说的是同一件事；超出预报覆盖的小时画成更淡的基座，与「这一小时不下雨」区分开
- 右侧：手绘感 SVG —— 十字街道 + 两团分散的雷达回波色块，色带随峰值档位切换
- 点整条弹出全屏雷达回放：**中央气象台（NMC）拼图 12 帧**、播放/暂停/拖动、Escape 关闭
- 雷达组件走动态 import，只在首次打开时才挂载；打开后**先出第一帧就撤遮罩**，其余 11 张后台预载，换帧命中缓存零延迟
- 打开期间每分钟回探最新帧并滚动追加到时间轴（上限 60 帧 / 6 小时），长时间停留不会停在旧帧
- 四档区域（全国 1349×1208 / 华东 774×1326 / 华北 954×949 / 中南 975×980）可在控制条切换；分区图官方只发原图一档，切过去时画质组自动灰化为「仅原图」
- 全国图有三档画质（原图 / 中图 825×739 / 小图 480×430），与四档速度一起可在控制条切换

**16 天预报**
- 列表 / 曲线双视图切换，两视图等高
- 曲线点位直接标注温度，图例配色与列表一致

**生活指数**（穿衣、防晒、户外、洗车、带伞、疾病风险）
- 每条一个结论短语 + 依据小字 + **一个语义图标**（洗车 = `car`，不宜洗车 = `car-off`）
- 好坏不靠颜色表达，靠图标语义，色弱用户同样可读
- 手机/平板 3 列 × 2 行，桌面一行六列

**设置面板**
- 毛玻璃强度：关 / 弱 / 标准 / 强
- 圆角：直角 / 标准 / 圆润
- 卡片图文布局：左右 / 上下
- 卡片数量：6 张 / 9 张（9 张多出空气质量、能见度、降水量）
- 设置写入 `localStorage`，脏数据自动退回默认档位

## 技术要点

**数据源**（全部免 API Key）

| 接口 | 用途 |
| --- | --- |
| `api.open-meteo.com/v1/forecast` | 实况 + 24h 逐小时 + 16 天预报（`forecast_days=16`） |
| `air-quality-api.open-meteo.com/v1/air-quality` | AQI、PM2.5、PM10 |
| `geocoding-api.open-meteo.com/v1/search` | 地名反查（备用） |
| `www.nmc.cn/rest/findAlarm` | 省级天气预警列表（中央气象台） |
| `image.nmc.cn/product/...` | NMC 雷达拼图 |
| `image.nmc.cn/assets/img/alarm/...` | NMC 预警图标 |

地名解析优先走本地表 `src/data/china-places.json`（394 个地级市 + 2814 个区县，区县挂在所属地级市下），命中即用，避免网络往返。

**雷达回放**

改用 [中央气象台（NMC）](http://www.nmc.cn/publish/radar/chinaall.html) 的全国雷达拼图：整幅 PNG 一次性显示，**不再叠 Leaflet 地图**，也就没有坐标系对齐问题。
- 图片按 6 分钟一档发布，URL 由 UTC 时间戳推算（`slotOf` 用 `Math.floor`，否则 07:35 会被推到还没发布的 07:36）。发布有 6–15 分钟延迟，所以从当前档往回最多探测 6 档找最新帧。
- **首帧先出**：探测到最新帧后立即建好 12 帧列表，只等第一张图 `decode()` 完成就撤遮罩开播，其余 11 张在后台并发预载，不等整批完成（避免冷缓存下 1.6–2.4 秒的空白等待）。若首帧 8 秒仍未落地也放行，真 404 由 `onerror` 单独标记。
- **开着时滚动刷新**：每 60 秒静默回探一次，把新发布的帧追加到时间轴尾部；超过 60 帧（6 小时）就从头裁掉并平移当前索引。回看旧帧的用户不会被强行拉回最新帧。
- 换帧走双缓冲 `<img>` + `visibility` 硬切（不是 opacity 过渡——两层半透明叠加会双重曝光），隐藏那张仍可继续加载与 `decode()`。
- 三档画质：`原图 1349×1208 / 中图 825×739 / 小图 480×430`（约 930/515/198 KB 每帧），按路径里有没有 `medium/`、`small/` 目录区分；换画质会重建整条帧列表。
- 图片是白底烘焙图（底图、省界、城市名、回波、图例都在一张图里），用 `invert(1) hue-rotate(180deg)` 转暗色主题；`hue-rotate` 是为了把反相后变品红的绿色回波绕回原色相。
- 响应带 `Access-Control-Allow-Origin: *`，但**没有 JSON 帧列表接口**，只能靠时间戳回推。

选 NMC 而非 RainViewer 的理由：单帧 0.27–0.62 秒（RainViewer 单块瓦片实测 1.3–12.4 秒）、6 分钟一帧（RainViewer 10 分钟）、当天有 70+ 帧可用（RainViewer 死限 13 帧）。代价是整图不能缩放、不能与自定义暗色底图叠加。

**性能取舍**
- 主包 ~174 KB（gzip 68 KB），Highcharts 单独分包 278 KB，雷达预览走动态 import（JS gzip 4.92 KB、CSS gzip 2.29 KB）
- 移除 Leaflet 与 Esri 底图后，WeatherHome 的 CSS 从 14.79 KB 降到 2.10 KB（Leaflet 样式不再打包）
- 雷达组件只在首次打开时挂载；打开后首帧先出、其余后台预载，之后换帧命中缓存零延迟

## 开发约定

这些约定来自踩过的坑，写进日志也写在这里：

1. **不要 `taskkill` 用户的浏览器或开发服务**。曾经误杀过，之后只允许 kill 自己 spawn 的进程 PID。
2. **质量门槛**：`npm run lint` 必须 0 错、`npm run build` 必须通过，才算完成。
3. **验证要看画面，不能只看状态码**。CARTO 瓦片返回 200 但是水印图——`curl -w %{http_code}` 证明不了任何事。
4. **Highcharts 的 `dataLabels.textOutline`** 会内嵌 `.highcharts-text-outline` tspan，用 CSS 改字体颜色会失效，必须改配置。
5. **Vue computed 在模板里自动解包**：`drift` 是 computed 时，模板写 `drift` 而不是 `drift()`。这个错曾让整个 `.weather-content` 不渲染。
6. **验证脚本的固定成本很高**（起无头浏览器 + 加载 + 截图 ≈ 2 分钟/次），因此脚本要一次跑完所有断言并直接落 JSON/日志，不要靠管道 `| tail` 观察。

## 已知限制与未完成的规划

### 可靠性

- **雷达数据依赖第三方**。NMC 无 SLA、无 JSON 帧列表接口，只能按 UTC 时间戳回推；发布有 6–15 分钟延迟，所以要从当前档往回探测最多 6 档。
- **雷达是整幅烘焙图**。省界、城市名、回波、图例都在一张 PNG 里，不能缩放叠加到自定义底图，只能整张显示；暗色主题靠 CSS 反相实现。
- **图片没有 `Cache-Control` 头**，但有 `Access-Control-Allow-Origin: *` 和 `Last-Modified`；换帧靠「首帧先出 + 其余后台预载 + 每分钟滚动追加」把图拉进内存，不依赖 HTTP 缓存。

### 未实现

1. **完全离线不可行**。雷达图是实时发布的滚动数据，缓存意义有限；且 NMC 无离线授权说明。断网时用不了雷达回放。
2. **PM2.5 之外的地图叠加未做**。NMC 只有雷达拼图这一种产品，没有可叠加到地图的瓦片；想要「任意缩放 + 叠加」只能自建瓦片服务（成本与授权都不划算）。
3. **多城市 / 收藏未做**。目前只有定位 + 搜索单个地点，没有城市列表、没有收藏、没有对比。
4. **预警只能看到标题，看不到正文**。NMC 详情页没有 CORS 头，浏览器 fetch 读不了「防御指南」全文，只能点开新窗口。另外接口只支持按省筛选，本地判定靠在标题里匹配城市名——如果某条预警的标题写的是上级市台发布、区域串里不含当前城市名，就会被漏掉（保守地少报，不会多报）。
5. **空气质量只有 AQI / PM2.5 / PM10**，没有 O₃、NO₂、SO₂、CO 的细分展示，也没有分时段预报；中国区无花粉数据（接口返回空），所以也没接。
6. **降水条目不区分降水类型**。只判断「有没有雨」，没有雨/雪/冻雨的分别文案；强度已用 12 小时柱条展示（`intensities`），但柱条只有粗细高低的档位，没有标出每格对应的具体时刻。
7. **无 PWA / 离线壳**。没有 Service Worker，断网时首次访问（或缓存已过期）整页不可用：能看到 0 占位骨架，但拉不到数据。24 小时内的缓存能让页面至少画出上一次的天气。
8. **无自动化测试**。`ui-review/` 里的验证脚本是开发期一次性工具，没有进 CI，也没有单测覆盖 `lifeIndex.js` / `rainOutlook.js` 这些纯函数规则——它们其实是最好测的部分。

### 工程债

- `weather.css` 单文件 1720 行，全局样式与组件样式混在一起，长期应拆分为设计令牌 + 组件级样式。
- `RainRadarPreview.vue` 1588 行（已从 2301 行的 Leaflet/RainViewer 版重写精简），帧探测、滚动刷新、预载、双缓冲播放与视图仍在同一 SFC，可抽成 `useRadarPlayer` composable。
- `ui-review/` 被 `.gitignore` 忽略，验证脚本不进版本库，换机器就丢失。若这些脚本要长期用，应单独放行或移到独立仓库。
